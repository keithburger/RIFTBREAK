# Content guide

Each content type has a skill with the full procedure (`.claude/skills/*`). This page is the
quick reference: where things live and what the definitions look like.

| Type | File | Count | Builder |
|---|---|---:|---|
| Weapons + evolutions | `src/content/weapons.ts` | 40 + 80 | `W(...)`, `E(...)` |
| Fusions | `src/content/weapons.ts` | 20 | `F(...)` |
| Elements + reactions | `src/content/elements.ts` | 10 + 45 | `R(a, b, name, col, desc, fx[])` |
| Enemies | `src/content/enemies.ts` | 64 | `E(...)` |
| Bosses | `src/content/bosses/*.ts` | 8 | `BossDef` + `BOSS_DEFS` in `registry.ts` |
| Biomes | `src/content/biomes.ts` | 4 | `BiomeDef` |
| Classes | `src/content/classes.ts` | 8 | object + `hooks` |
| Passives | `src/content/passives.ts` | 24 | `P(id, name, desc, max, ...mods)` |
| Relics | `src/content/relics.ts` | 26 | `R(id, name, rarity, desc, mods?, hooks?)` |
| Encounters | `src/content/encounters.ts` | 12 | `EncounterDef` |
| Modes, meta upgrades | `src/content/modes.ts` | 7, 10 | objects |

## Ops DSL
`path op value` strings applied to a params/stats object: `*` multiply, `+` add, `=` assign
(numbers, hex numbers or words). Nested paths are created on demand.
`'dmg*1.3'` · `'count+1'` · `'explode=46'` · `'zone.r*1.8'` · `'status.s=freeze'` · `'kind=beam'` · `'x.spin=1'`

## Weapon example
```ts
W('ember_carbine', 'Ember Carbine', 'fire', 'Rapid bolts that set enemies ablaze.',
  { kind: 'shot', dmg: 7, cd: 0.38, speed: 560, range: 460, area: 7, status: st('burn', 0.4, 3, 0.5), sprite: 'p_bolt' },
  [['dmg*1.3'], ['count+1'], ['cd*0.8', 'dmg*1.15'], ['pierce+1', 'dmg*1.25']],          // ranks 2-5
  E('inferno_repeater', 'Inferno Repeater', 'haste', 'Bolts detonate…', ['explode=46', 'burst=3', 'cd*1.5', 'dmg*1.3']),
  E('phoenix_lance', 'Phoenix Lance', 'piercing', 'Bolts pierce everything…', ['pierce+99', 'trailZone=0.08', 'zone.r=22', …]))
```
Shared projectile modifiers (any `shot`-like kind): `pierce`, `homing`, `bounce`, `split`,
`explode`, `chain`, `returns`, `grow`, `zone` (pool on hit/expiry), `trailZone`, `tickR` (aura orb),
`status`, `kb`, `exec`, `lifesteal`, `aim` (`near|facing|move|random|strong|multi`), `burst`.
Kind-specific switches (`x.*`) are documented above each `registerKind` in `sim/weaponKinds.ts`.

## Relic with hooks
```ts
R('frenzy_engine', 'Frenzy Engine', 2, 'Kills grant stacking attack speed (up to +40%) that decays.', undefined, {
  onKill(w) { const rs = w.player.rs; rs.frenzy = Math.min(40, (rs.frenzy ?? 0) + 1); },
  tick(w, dt) { const p = w.player; p.rs.frenzy = Math.max(0, (p.rs.frenzy ?? 0) - dt * 4); p.dynHaste *= 1 + p.rs.frenzy * 0.01; },
})
```

## After any change
```bash
npm run validate          # ids, references, behavior names, counts
npm run test:fast         # generated per-item tests pick the new content up automatically
npm test && npm run manifest   # refresh content-manifest.json (generated — never hand-edit)
```

## `content-manifest.json`
Generated by `scripts/build-manifest.ts` from the registries and the last `npm test` report. Per
item: `implemented` (registered + validation clean), `art` (procedural sprite/icon exists),
`integrated` + `reach` (how a player encounters it), `verified` + `test` (the automated test that
covers it and whether it passed in the recorded run).
